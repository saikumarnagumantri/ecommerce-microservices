System

Architecture

Both apps talk to one door, the API gateway. It checks the login token and the role, then passes the request to the right service. Services do not open to the public.

Storage

Data

Each service owns its tables. Orders keep a snapshot of names, prices and the address, so later edits never rewrite history.

users

  • usersid, email (unique), passwordHash, name, phone, role, createdAt
  • addressesuserId, line1, line2, city, state, postalCode, country, isDefault

catalog

  • categoriesname, parentId
  • productsname, description, categoryId, brand, originalPrice, discountPrice, isActive
  • product_featuresproductId, label, value, sortOrder
  • product_mediaproductId, type IMAGE | VIDEO, url, sortOrder, isPrimary

inventory

  • inventoryproductId, stock, reserved, updatedAt
  • inventory_movementsproductId, delta, reason RESTOCK | ORDER | CANCEL | ADJUST, refId

cart

  • cartsuserId
  • cart_itemsuserId, productId, quantity · one row per user + product

orders

  • ordersuserId, status, totalAmount, shippingAddress (snapshot), paymentMethod
  • order_itemsorderId, productId, name + price snapshot, quantity
  • order_eventsorderId, status, note, actorId, createdAt
  • shipmentsorderId, carrier, trackingNumber, dispatchedAt, deliveredAt

Definition of done

  • Acceptance criteria met and shown by running the service or app.
  • Unit tests for business rules pass; the service builds with no type errors.
  • Endpoints validated and listed in Swagger.
  • Admin routes protected by role checks.
  • No secrets committed; settings come from environment.
  • Docs updated where behaviour changed.

Not in this sprint

  • Online payment (Stripe, Razorpay)
  • Email, SMS and push notifications
  • Reviews, wishlists, coupons, card offers at checkout
  • Multiple warehouses, refunds
  • App-store release

Risks

  • 191 points is a lot for one sprint. Backend goes first so the apps never wait; every step stays shippable.
  • Overselling. Row lock in the reserve step, proven with a parallel-request test.
  • No shared transaction across services. Reserve first, save, and release on failure.
  • Large videos. Size limits, and range requests so playback streams.
